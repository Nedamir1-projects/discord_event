# Discord Bots Platform

Монорепозиторий с двумя Discord-ботами: **Economy Bot** для игровой экономики и взаимодействия с участниками и **Event Master** для управления событиями и административными операциями. Общий пакет `packages/shared` содержит бизнес-логику и доступ к PostgreSQL через Prisma.

## Компоненты

| Путь | Назначение |
| --- | --- |
| `apps/economy-bot` | Баланс конфет, награды за активность, магазин, расы, способности игроков и игровые команды событий. |
| `apps/event-master` | Административная панель, префиксные команды администраторов, настройка и управление событиями. |

Оба приложения работают как отдельные Discord-приложения и используют общую базу данных. Запускайте каждый бот со своим токеном и Application ID. Секреты хранятся в корневом `.env`, который не следует добавлять в Git.

## Возможности Economy Bot

### Экономика и активность

- Начисляет конфеты за сообщения в разрешённых текстовых каналах. Настройки ограничивают частоту начислений, число наград в час и повторяющиеся сообщения.
- Учитывает время в разрешённых голосовых каналах. Можно отдельно исключить AFK-каналы и игнорировать пользователей с self-deaf.
- Хранит баланс и историю операций в PostgreSQL. Операции имеют уникальные идентификаторы, чтобы повторный запрос не начислял награду или не списывал конфеты второй раз.
- Поддерживает рейтинг игроков и игровые профили.

### Магазин и расы

- `/shop` показывает доступный каталог обычных товаров по пять на страницу; покупка запускается кнопкой с номером товара.
- Администратор может открыть `/panel` → «Магазин», добавить товар и указать необязательный ID роли, которая выдаётся при покупке. Для выбранного товара можно менять название, описание, цену, лимит покупок на одного игрока, доступность и ID роли.
- Для выдачи роли у Economy Bot должно быть право «Управлять ролями», а роль товара должна находиться ниже его высшей роли на сервере.
- `/race` показывает каталог рас на русском языке; во время активной «Ночи охоты» расу можно купить кнопкой. При настроенной Discord-роли бот попробует назначить её автоматически.
- Игрок начинает с расой `Mortal` и может купить только одну расу. Повторный выбор другой расы отклоняется до списания конфет.
- Покупка расы доступна, только когда событие «Ночь охоты» имеет статус `active`. До запуска команда показывает список рас, но не позволяет купить их.
- `/abilities` показывает описание выбранной расы. В коде также есть команды способностей `/bite`, `/curse` и `/possess`; доступность способности зависит от расы, настроек и ограничений события.

Стандартный каталог рас задаётся в `packages/shared/src/economy-service.ts`: Смертный, Ведьма, Оборотень, Вампир и Призрак. Внутренние ID рас остаются латинскими, но в командах отображаются русские названия. Цены и описания хранятся в таблице рас. Для назначения Discord-ролей нужны ID ролей в настройках события и право `Manage Roles` у Economy Bot; роль бота должна быть выше игровых ролей.

### Игровые события

- **Ночь охоты:** регистрация участников, учёт игровой активности, босс с настраиваемыми действиями и фазами, таблица результатов и выдача наград.
- **Хэллоуин:** сюжетные главы, загадки и подсказки, квесты с наградами, секретная роль, голосования и восстановление состояния события после перезапуска.
- **Общие тыквы:** проверка зарегистрированных сообщений с тыквами, сбор прогресса и отслеживание найденных тыкв.

Пользовательские команды для этих функций: `/hunt`, `/halloween` и `/pumpkin`. Их подкоманды отображаются в Discord после регистрации команд приложения.

## Возможности Event Master

- `/panel` открывает приватную административную панель. Панель предоставляет интерфейс для настройки поддерживаемых событий, заданий, загадок и других игровых данных.
- Префиксные команды администрирования начинаются с `<`; для совместимости также принимается `>`. Примеры: `<help`, `<panel`, `<events`, `<event start ID`, `<give USER_ID AMOUNT`.
- Административные команды проверяют Discord ID по `ADMIN_IDS`. Укажите несколько ID через запятую, пробел, `;` или перенос строки, например `ADMIN_IDS=111111111111111111,222222222222222222`. Критичные операции требуют подтверждения и записываются в журнал аудита.
- Состояние событий и незавершённых операций хранится в базе. После рестарта Event Master восстанавливает работу по сохранённому состоянию и сверяет изменения игровых ролей с Discord.

## Игровой процесс: когда запускать команды и что они возвращают

Slash-команды с результатами для игрока отвечают приватно (ephemeral), если отдельно не сказано иное. Сначала администратор создаёт событие и настраивает его в Event Master; затем запускает его. Команды участия имеют смысл только после запуска и до окончания события. Если условия не выполнены, сервис отклоняет действие и Discord показывает сообщение об ошибке.

### Обычные команды и магазин

| Команда | Когда использовать | Что происходит и какие есть исходы |
| --- | --- | --- |
| `/ping` | В любое время, чтобы проверить, что процесс бота подключён к Discord. | Отвечает `Pong!`. Это проверка связи с Discord, не проверка всех игровых настроек или базы. |
| `/balance` | В любое время. | Показывает текущие конфеты и до пяти последних операций с суммой и причиной. При пустой истории пишет, что операций ещё нет. |
| `/profile` | В любое время. | Показывает имя игрока, баланс и расу. Новый профиль создаётся со значениями по умолчанию при первом обращении к сервису. |
| `/leaderboard` | В любое время. | Показывает до десяти профилей с наибольшим количеством конфет. Если игроков нет, сообщает, что таблица пока пуста. |
| `/shop` | В любое время. | Показывает доступные товары по пять на страницу; кнопки `1`–`5` покупают соответствующий товар, стрелки переключают страницы. Если у товара указана роль, бот проверяет возможность её выдать до списания конфет. Эта команда не показывает каталог рас — для этого используйте `/race`. |
| `/race` | До или во время события. | Показывает каталог с русскими названиями и кнопками. Кнопки покупки активны только во время «Ночи охоты» со статусом `active`; для покупки нужны достаточный баланс и профиль со стартовой расой `Смертный`. После выбора другая раса этой логикой уже не покупается. Бот сохраняет выбор и пробует выдать Discord-роль из настроек события. |
| `/abilities` | После выбора расы или чтобы посмотреть описание стартовой расы. | Показывает расу профиля и её описание из каталога. Это информационная команда; она не выдаёт права на каналы и не запускает способность. |

**Важно о расах:** выберите нужную расу кнопкой в `/race`. Названия в интерфейсе переведены на русский; внутренние ID не вводятся вручную. Один профиль может купить расу только из стартового состояния «Смертный» и только один раз. Каталог товаров можно менять через `/panel` → «Магазин»; для редактирования каталога рас пользовательского интерфейса пока нет.

### «Ночь охоты» и способности рас

| Команда | Когда использовать | Что происходит и какие есть исходы |
| --- | --- | --- |
| `/hunt status` | Пока есть событие «Ночь охоты» в состояниях waiting, active или paused. | Показывает название, статус, число участников, дату окончания (если настроена), а также имя босса, его HP, фазу и исход боя. Если босса ещё не настроили, это будет указано отдельно. Если подходящего события нет — ответ «Событие сейчас не настроено». |
| `/hunt join` | Пока регистрация открыта или событие активно. | Записывает игрока в участие и сохраняет его текущую расу/фракцию; повторное присоединение не создаёт дубль. В обычном сценарии игрок нажимает кнопку в сообщении регистрации, которое администратор указал при создании события. Во время паузы или после завершения присоединиться нельзя. |
| `/hunt attack action` | Когда событие активно и настроенный бой с боссом ещё открыт. `action` должен совпадать с ID действия из настроек босса. | Сервис сам регистрирует участника при первой атаке, рассчитывает урон по действию, расе, фазе и эффектам, уменьшает HP и учитывает личный урон. Ответ показывает нанесённый урон и оставшееся здоровье; повтор того же Discord-взаимодействия считается уже учтённым. Ошибки: неизвестное действие, событие не активно, бой закрыт или истёк. При 0 HP босс получает исход `victory`; дальнейшая атака не проходит. |
| `/bite player` | Когда у пользователя раса `Vampire`; между успешными укусами действует кулдаун 4 часа. Цель должна быть другим игроком с расой `Mortal`. | Переводит от цели вампиру до 15 конфет (не больше остатка на балансе цели) и показывает украденную сумму. Отказ будет, если неверная раса цели/нападающего, цель — сам игрок, у цели 0 конфет или способность на перезарядке. |
| `/curse player` | Когда у пользователя раса `Witch`; повторное проклятие доступно после окончания кулдауна в 1 час. | Создаёт эффект проклятия на 1 час; ответ указывает время окончания. Нельзя проклясть Ведьму (`Witch`). Если включён `WITCH_CURSE_ROLE_ID`, бот также пытается выдать целевую роль; сама механика ограничения эмодзи Discord этим кодом не реализуется. |
| `/possess player` | Когда у пользователя раса `Ghost`; после применения действует кулдаун 30 минут. | Создаёт эффект `possession` на 30 минут и показывает время окончания. Если настроен `GHOST_EFFECT_ROLE_ID`, бот пробует выдать эту роль цели. Текущая реализация не копирует ник или аватар администратора и не создаёт настоящую маскировку. |

Награды за обычную активность и прогресс «Ночи охоты» считаются отдельно. За принятые сообщения начисляется награда после достижения порога `TEXT_REWARD_EVERY`. За голос начисляется `VOICE_REWARD_CANDIES` конфета(ы) за каждые `VOICE_REWARD_EVERY_MINUTES` минут в разрешённом канале; по умолчанию — 1 конфета за 5 минут. Голосовые каналы перечисляются в `VOICE_CHANNEL_IDS`; значение `*` разрешает все голосовые каналы. Каналы из `VOICE_AFK_CHANNEL_IDS` всё равно исключаются, а при пустом списке разрешённых каналов голосовая награда выключена. Время с отключённым звуком также игнорируется по умолчанию. Во время активной «Ночи охоты» активность дополнительно учитывается в прогрессе события и может давать отдельную награду из его настроек.

### «Проклятие Хэллоуина»

Сначала администратор создаёт событие, главы, загадки, квесты и, если нужно, голосования через панель. Участие открывается только после статуса `active`; в ожидании и после окончания игрок не сможет присоединиться.

| Команда | Когда использовать | Что происходит и какие есть исходы |
| --- | --- | --- |
| `/halloween join` | Во время активного события и до его срока окончания. | Добавляет игрока в участники. Ответ предлагает читать историю через `/halloween story`. Повторное присоединение безопасно. |
| `/halloween story` | После `/halloween join`, во время активного события, когда открыта глава по расписанию. | Возвращает очередную непрочитанную главу с порядковым номером, названием и текстом. Закрытая по времени глава отклоняется; если новых глав нет, сообщает об этом. |
| `/halloween role` | Когда событие создано. | Приватно показывает секретную роль: «предатель» или обычный «участник». |
| `/halloween hint riddle` | После `/halloween join`, пока событие активно и загадка открыта по расписанию. | Показывает следующую доступную подсказку. Если загадка уже решена — сообщает об этом; если подсказки закончились — сообщает, что новых нет. |
| `/halloween answer riddle answer` | После `/halloween join`, пока событие активно и загадка открыта. | При верном ответе начисляет заданную награду в конфетах и подтверждает её; повторное получение не начисляет конфеты ещё раз. При неверном ответе предлагает попробовать снова или взять подсказку. |
| `/halloween quests` | Во время события после настройки доступных квестов. | Показывает открытые квесты: название, ID, награду, описание, условия и зависимости. Если открытых квестов нет — так и сообщает. |
| `/halloween claim quest` | После выполнения условий конкретного квеста. | Отмечает квест выполненным и выдаёт награду. Повторная попытка сообщает, что квест уже засчитан, и не выдаёт вторую награду. Команда не проверяет внешние условия автоматически: игрок отмечает выполнение сам, а сервис проверяет доступность и зависимости. |
| `/halloween polls` | Когда администратор создал открытое голосование. | Показывает открытые опросы, их ID, вопрос и варианты. Если активных опросов нет, сообщает об этом. |
| `/halloween vote poll choice` | Пока указанное голосование открыто; `choice` должен совпадать с одним из вариантов. | Сохраняет один голос участника в опросе и отвечает «Ваш голос учтён». Повторный голос или неверный вариант отклоняется сервисом. |

Если событие не создано, любая команда `/halloween` сообщает, что событие ещё не создано. При неактивном или просроченном событии команды участия/прогресса завершаются отказом.

### Общие тыквы

1. Администратор регистрирует активные слоты тыкв и правильные сообщения через Event Master.
2. Игрок вызывает `/pumpkin` и выбирает доступный номер в приватном меню.
3. Игрок отправляет ссылку на сообщение. Бот получает сообщение через Discord API и проверяет сервер, канал, сообщение, автора и наличие нужной тыквы.
4. При успешной проверке слот засчитывается, конфеты выдаются один раз. Повторный claim не дублирует награду. Неверная/недоступная ссылка, другой сервер, другой автор или сообщение без нужной тыквы приводят к отказу. Если активных тыкв нет, команда сообщает, что пока нечего искать.

### Панель Event Master: подготовка события

`/panel` открывает личную панель администратора. Её кнопки работают только для владельца панели и пока сессия действительна. Доступ к админ-командам проверяется по `ADMIN_IDS`.

Обычный цикл «Ночи охоты»:

1. В панели выберите **Ночь охоты**, заполните параметры и ID текстового канала регистрации. Бот отправит туда эмбед с кнопкой **Участвовать**. Событие появляется в ожидании (`waiting`); нажатие кнопки записывает игрока и сохраняет его текущую расу. `/hunt join` остаётся альтернативным способом присоединиться.
2. Настройте длительность/срок, награды активности, параметры босса, действия, фазы и правила урона. Для выдачи ролей задайте Discord-роль для каждой расы в provisioning-настройке и убедитесь в иерархии ролей.
3. Нажмите **Запустить** либо используйте `<event start EVENT_ID`. Статус становится `active`; с этого момента работают покупка рас, присоединение, регистрация активности и бой, если босс настроен.
4. Участники нажимают **Участвовать** в сообщении регистрации (или используют `/hunt join`), зарабатывают конфеты/прогресс разрешённой активностью и атакуют босса через `/hunt attack action`.
5. Администратор ставит событие на паузу/возобновляет его или завершает. По завершении охота рассчитывает награды по сохранённому прогрессу; повторная обработка наград идемпотентна.

Для «Проклятия Хэллоуина» создайте событие и содержимое (главы, загадки, квесты, опросы), назначьте предателя при необходимости и переведите событие в `active`. После этого игроки могут присоединяться и использовать команды из таблицы выше. Окончание или ручное завершение закрывает участие.



| Подкоманда | Когда и для чего |
| --- | --- |
| Кнопка **Продвинуть** в `#миссии` | Повстанец нажимает кнопку у открытой миссии и вводит вклад в форме. Бот проверяет фракцию, заключение и активность события, затем обновляет прогресс на карточке; повтор одного Discord-взаимодействия не засчитывается повторно. |


## Требования и настройка

- Node.js `24.11.x` и npm `11` или новее.
- PostgreSQL 17 или новее; для локальной разработки можно использовать Docker Compose.
- Два приложения Discord Developer Portal: отдельное для Economy Bot и для Event Master.

### Установка

PowerShell:

```powershell
Copy-Item .env.example .env
npm install
docker compose up -d postgres
npm run db:generate
npm run db:deploy
```

macOS/Linux:

```sh
cp .env.example .env
npm install
docker compose up -d postgres
npm run db:generate
npm run db:deploy
```

Затем заполните `.env`: токены ботов, Application ID, URL базы данных и Discord ID администраторов. Для разработки укажите тестовый сервер в `GUILD_ID`: его slash-команды обновляются быстрее. Оставьте поле пустым для глобальной регистрации команд.

### Intents и права Discord

Включите нужные privileged intents в Discord Developer Portal:

- Economy Bot: **Message Content** для обработки текстовой активности и префиксных игровых сообщений; **Server Members** для операций с участниками и ролями.

Выдайте ботам только нужные серверные права: просмотр каналов, чтение истории сообщений, отправка сообщений, использование slash-команд и встраивание ссылок. Для операций с расами и временными игровыми ролями Economy Bot или Event Master может требоваться `Manage Roles`. Роль бота должна располагаться выше ролей, которыми он управляет. Не выдавайте ботам Administrator.

Если используете команды активности, ограничьте `TEXT_CHANNEL_IDS` и `VOICE_CHANNEL_IDS` нужными каналами. Для регистрации тыкв Economy Bot должен иметь доступ к каналу сообщения и возможность проверить его по Discord API.

## Запуск и команды Discord

Зарегистрируйте slash-команды обоих приложений после настройки `.env`:

```sh
npm run commands:economy
npm run commands:events
```

Режим разработки (запустить команды в отдельных терминалах):

```sh
npm run dev:economy
npm run dev:events
```

Production-сборка и запуск:

```sh
npm run build
npm run start:economy
npm run start:events
```

Для одновременного запуска двух production-процессов используйте `npm run start:all`.

## Переменные окружения

Основные переменные находятся в `.env.example`:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения PostgreSQL. |
| `ECONOMY_BOT_TOKEN`, `EVENT_MASTER_BOT_TOKEN` | Токены двух Discord-ботов. |
| `ECONOMY_CLIENT_ID`, `EVENT_MASTER_CLIENT_ID` | Application ID для регистрации slash-команд. |
| `GUILD_ID` | Необязательный ID сервера для быстрой регистрации команд во время разработки. |
| `ADMIN_IDS` | Discord ID администраторов через запятую. |
| `BOT_CONTROL_CHANNEL_ID` | Необязательный канал управления ботом. |
| `TIMEZONE` | Часовой пояс, используемый настройками событий; по умолчанию `UTC`. |
| `BOT_PREFIX` | Префикс команд Economy Bot; по умолчанию `!`. |
| `TEXT_CHANNEL_IDS` | Список каналов для наград за текстовую активность. |
| `TEXT_REWARD_EVERY`, `TEXT_REWARD_CANDIES` | Частота и размер текстовой награды. |
| `TEXT_MIN_INTERVAL_SECONDS`, `TEXT_MAX_PER_HOUR` | Ограничения частоты текстовых наград. |
| `TEXT_REPEAT_WINDOW`, `TEXT_REPEAT_LIMIT` | Защита от повторяющихся сообщений. |
| `VOICE_CHANNEL_IDS`, `VOICE_AFK_CHANNEL_IDS` | Разрешённые голосовые каналы (`*` — все) и исключённые AFK-каналы. |
| `VOICE_IGNORE_SELF_DEAF` | Не учитывать время пользователя с отключённым звуком; по умолчанию включено. |
| `VOICE_REWARD_EVERY_MINUTES`, `VOICE_REWARD_CANDIES` | Период и сумма обычной голосовой награды; по умолчанию 1 конфета за 5 минут. |
| `WITCH_CURSE_EFFECT`, `WITCH_CURSE_ROLE_ID`, `GHOST_EFFECT_ROLE_ID` | Настройка визуальных эффектов способностей рас. |

Списки Discord ID задаются через запятую. Не публикуйте `.env` и не используйте production-секреты для локальных тестов.

## База данных и разработка

`packages/shared/prisma/schema.prisma` описывает профили, балансы и транзакции, каталог и покупки, события, прогресс и аудит. Миграции находятся в `packages/shared/prisma/migrations`.

- `npm run db:generate` генерирует Prisma Client.
- `npm run db:deploy` применяет существующие миграции без создания новых.
- `npm run db:migrate` используется при локальном изменении схемы и создании миграции. Проверьте и зафиксируйте созданный SQL.


## Проверки и тестовая база

```sh
npm run build
npm run typecheck
npm run lint
npm run format:check
npm test
```

Интеграционные тесты используют отдельную тестовую базу через `HUNT_TEST_DATABASE_URL`. Для проверки миграций на чистой базе задайте URL отдельной пустой базы как `DATABASE_URL` и `HUNT_TEST_DATABASE_URL`, затем выполните `npm run db:deploy` и `npm test`. Некоторые тесты создают и удаляют тестовые строки: никогда не указывайте production URL. Discord API в тестах заменяется адаптерами.

## Известные ограничения

- Slash-команды регистрируются только отдельными командами `npm run commands:economy` и `npm run commands:events`.
- Админ-панель позволяет управлять товарами магазина и ролями за покупку. При обновлении базы примените миграции командой `npm run db:deploy` до запуска ботов. Каталог рас пока управляется через общие сервисы и данные базы.
- Роли и каналы Discord — внешние ресурсы: транзакция PostgreSQL не может атомарно откатить уже выполненный запрос к Discord API. Проверьте права ботов и иерархию ролей до запуска событий.
- Сначала проверяйте конфигурацию и игровые сценарии на отдельном тестовом Discord-сервере.
